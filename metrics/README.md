## 3. 무음 노이즈 처리

### 계산 방식과 단위

기존 계산은 `mean(abs(log(Sx + 1e-8) - log(Sy + 1e-8)))`입니다.
`S`는 STFT 복소 결과의 절댓값입니다. 무음은 `log(1e-8)`이 되므로,
작은 잡음도 매우 많은 빈도/시간 칸에서 큰 차이를 만듭니다.

1차 개선(v1)은 `L(S) = log(max(S, 0.000512))`,
`d_v1 = mean(abs(L(Sx) - L(Sy)))`였습니다. epsilon을 더하지 않습니다.
하한 이하인 칸은 같은 값이 되며, 하한보다 큰 칸은 원래 크기 차이를 유지합니다.
하한은 **STFT 크기 단위**이고 로그 적용 직전에 양쪽에 똑같이 적용합니다.
최종 거리의 단위는 자연로그 차이이며 **dB가 아닙니다**.

현재 v2도 같은 로그·하한을 쓰지만 시간 프레임의 집계 방식을 바꿨습니다.
주파수 bin 수를 `F`, 프레임 번호를 `t`라 하면 다음과 같습니다.

```text
e[t] = sum_k abs(L(Sx[k,t]) - L(Sy[k,t])) / F
active[t] = any_k (Sx[k,t] > floor OR Sy[k,t] > floor)
Ex[t] = sum_k Sx[k,t]**2
Ey[t] = sum_k Sy[k,t]**2
w[t] = active[t] * max(Ex[t], Ey[t])
d_v2 = sum_t w[t]*e[t] / sum_t w[t]
```

활성 프레임이 하나도 없으면 나눗셈 대신 Python `float` **0.0**을 반환합니다.
교집합(AND)이 아닌 **합집합(OR)**이므로 한쪽에만 있는 소리도 포함합니다.
활성인 한쪽 소리의 에너지는 양수여서 가중치도 양수입니다.
아주 작은 잡음이 모든 STFT bin에서 하한 아래이면 두 로그 스펙트럼이 같고 결과는 0입니다.

실제 에너지 계산은 overflow를 막기 위해 양쪽 전체에 **하나의 공통 참조값**을 사용해
제곱합니다. 이는 위 식의 모든 가중치를 같은 상수로 나누는 것이므로 평균에서 상쇄됩니다.
로그 스펙트럼의 크기는 바꾸지 않으며 입력별 음량 정규화가 아닙니다.

설정은 FFT/창 길이 2048, hop 512, 주기적 Hann 창, `center=True`,
0 패딩입니다. v2는 STFT 전에 **양 끝에 고정 1024개의 0**을 추가해
원래 신호와 겹치는 양 끝 분석 창을 완성합니다. 고정 추가분 중 공통 무음 프레임은 제외됩니다.
입력은 동일한 표본율·정렬·샘플 크기
기준이어야 합니다. 보통 PCM full scale을 진폭 1로 둡니다. 함수를 호출하기 전에
호출자가 표본율과 정렬을 맞춰야 하며, 함수 자체는 이 정보를 받지 않습니다.
입력별 peak 정규화나 소리 크기 보정은 하지 않습니다.

진폭 1인 FFT bin 중심 순음은 내부 프레임에서 STFT peak가
`sum(Hann)/2 = 512`입니다. 이 **고정 참조**에 대해
`20*log10(S/512)`로 표시한 **-120 dB**를 사용합니다.
즉 `512 * 10**(-120/20) = 0.000512`입니다.
이는 해당 순음 참조의 값이며, 모든 주파수·잡음의 파형 RMS가 -120 dB일 때
잘린다는 뜻은 아닙니다. DC, 경계 프레임, FFT bin 사이 주파수에서는 대응이 다릅니다.
입력별 측정 peak를 참조하지 않습니다. 진폭이 1보다 큰 렌더링 출력도 그대로 비교합니다.
정수 PCM을 전달한다면 호출자가 공통 full-scale 기준으로 실수 변환해야 합니다.

### 방식 선택

| 후보 | 검토 결과 |
|---|---|
| 고정 STFT 크기 하한 | 구현이 단순하고 두 입력의 절대 음량 차이를 보존하므로 선택 |
| 고정 참조의 dB 하한 | 위 고정 하한을 설명하고 선택하는 표현으로 사용 |
| 각 신호 peak에 상대적인 dB 하한/정규화 | 두 입력의 음량 비교를 바꿀 수 있어 사용하지 않음 |
| 동적 잡음 추정 | 추가 설정과 실제 잡음 데이터가 필요해 사용하지 않음 |

### 긴 무음의 원인과 개선 방법 비교

22050 Hz, 길이 22050, 진폭 0.5의 440 Hz 순음과 진폭 절반 신호에
동일한 무음을 붙여 재현했습니다. v1은 전체 프레임이 44 → 87 → 130 → 259개로
늘어나지만 활성 프레임은 44 → 46 → 46 → 46개입니다.
나머지 프레임은 오차 0인데 평균의 분모에는 포함되어 거리를 계속 줄입니다.
추가로 STFT의 경계 창이 생기므로 단순히 활성 프레임 수로만 나누어도
무음 0초와 1초 사이에 약 12% 차이가 남습니다.

| 방법 | 장점과 한계 | 선택 |
|---|---|---|
| 양쪽 모두 활성인 프레임만 평균(AND) | 한쪽에만 있는 소리를 지워 복원 실패를 놓침 | 제외 |
| 어느 한쪽이 활성인 프레임 평균(OR) | 공통 무음 희석 제거, 약한 경계 창도 동일 가중치라 경계 영향이 큼 | 단독 사용하지 않음 |
| OR + 공통 에너지 가중치 | 실제 한쪽 소리 포함, 약한 경계 영향 감소, 조용한 오류의 기여도도 작아짐 | 선택 |
| 공통 활동 구간을 잘라 평가 | 외곽 무음 제거 가능, 내부 긴 쉼표는 별도 처리가 필요하고 자르는 위치에 따라 창이 달라짐 | 미채택 |
| 활동 구간별로 따로 STFT | 구간별 평가 가능, 검출 임계값·경계·구간 합산 규칙이 더 필요 | 미채택 |

입력별로 따로 자르거나 정규화하면 원래 시간 관계·음량 차이가 사라질 수 있어 사용하지 않습니다.
선택한 방식에 양 끝 창 완성을 더하면 뒤에 붙인 정확한 0의 길이에 따른 차이도 없어집니다.

| 추가 무음 | v1 전체 평균 | OR 평균 | OR+에너지, 창 완성 전 | 선택한 v2 |
|---|---:|---:|---:|---:|
| 0초 | 0.107796 | 0.107796 | 0.093888 | **0.095110** |
| 1초 | 0.063784 | 0.120636 | 0.094585 | **0.095110** |
| 2초 | 0.042687 | 0.120636 | 0.094585 | **0.095110** |
| 5초 | 0.021426 | 0.120636 | 0.094585 | **0.095110** |

v1에서 2초·5초 사례가 옛 기준 0.049579를 통과하던 역전이 재현되었습니다.
v2의 네 점수는 모두 새 잠정 기준 0.043171보다 커서 실패로 유지됩니다.
회귀 테스트는 20초 무음, hop에 맞지 않는 추가 무음 길이도 확인합니다.
공통 선행 무음은 같은 hop 격자에서 불변인 것도 확인했습니다.
hop의 배수가 아닌 선행 삽입이나 내부 구간 재배치는 STFT 격자를 바꿀 수 있어
모든 시간 이동에 대한 완전한 불변성을 보장하는 지표는 아닙니다.

### 후보 비교와 기본값 근거

표본율 22050 Hz, 길이 22050, RNG `default_rng(42)`를 사용했습니다.
작은 잡음의 표준편차는 `1e-6`입니다. 조용한 순음은 진폭 `1e-5`,
주파수 `22050*41/2048` Hz입니다. 후보는 동일한 입력으로 비교했습니다.

| 사례 | -140 dB 하한 | -120 dB 하한 | -100 dB 하한 |
|---|---:|---:|---:|
| 무음 ↔ 작은 잡음 | 0.003744 | 0 | 0 |
| 무음 ↔ 조용한 순음 | 0.015627 | 0.005416 | 약 2.2e-19 |

-140 dB는 이 잡음 일부를 남기고, -100 dB는 조용한 순음도 사실상 지웠습니다.
-120 dB는 비교한 후보 중 이 잡음을 모두 잘라내면서 조용한 순음을 보존하는
가장 낮은 하한이었습니다. 실제 녹음의 잡음 분포로 최적화한 값이나 청각 한계는 아닙니다.
이 수치와 합성 실험만으로 모든 장비에 맞는 최적값이라고 주장할 수 없습니다.

### 로그 하한·집계 방식별 거리

같은 실험에서 일반 순음은 진폭 0.5, 440 Hz이며 1초 길이입니다.

| 비교 | 최초 epsilon 방식 | v1 하한/전체 평균 | 현재 v2 |
|---|---:|---:|---:|
| 동일한 신호 | 0 | 0 | 0 |
| 무음 ↔ 표준편차 1e-6 잡음 | 7.630617 | 0 | 0 |
| 일반 순음 ↔ 같은 순음 + 위 잡음 | 3.354323 | 0.000610 | 0.000614 |
| 일반 순음 ↔ 진폭 절반 | 0.621196 | 0.107796 | 0.095110 |
| 440 Hz ↔ 880 Hz | 1.289800 | 0.462696 | 0.454794 |
| 무음 ↔ 진폭 1e-5 조용한 순음 | 0.506134 | 0.005416 | 0.005397 |

의도된 변화는 낮은 에너지의 칸이 점수를 지배하지 않도록 하는 것입니다.
따라서 기존 정상 신호의 수치도 달라지며, 예전 점수 기준을 재사용하면 안 됩니다.
음량·주파수 차이는 여전히 양수이고, 하한 위의 광대역 신호를 절반으로 줄이면
거리 `ln(2)`를 유지하는 것도 테스트했습니다. 다만 두 스펙트럼이 모두 하한 아래인
칸의 차이는 사라집니다. v2는 공통 무음에 가중치 0을 주어 긴 무음 희석을 제거합니다.
다만 에너지 가중치 때문에 큰 소리와 함께 있는 조용한 구간의 오류는 적게 반영됩니다.
한쪽의 조용한 소리를 무조건 제외하지는 않지만 모든 국소 오류의 검출을 보장하지는 않습니다.
위상만 다른 소리를 완전히 구별하는 지표도 아닙니다.

빈 입력, 1차원이 아닌 입력, NaN/Inf, 복소수·문자·boolean 샘플은 `ValueError`입니다.
STFT 계산 중 overflow가 발생한 극단적 입력도 `ValueError`로 거부합니다.
길이가 다른 입력도 기존처럼 오류를 냅니다. 입력을 바꾸거나 결과를 임의의 큰 점수로
대체하지 않습니다. 길이 1처럼 짧은 비어 있지 않은 입력도 허용하며 librosa 경고가 날 수 있습니다.

## 4. 정답 대비 오차 기준

### A. 오디오 스펙트럼 거리: 합성 실험에서만 잠정 기준

저장소에는 실제 오디오 파일, 합성 정답/예측 결과가 없습니다.
`target_sample.data.json`의 WAV 경로는 예제입니다.
따라서 실제 기타 데이터의 **최종 기준 확정 불가**입니다.

대신 1초 합성 순음과 감쇠하는 3배음 dry 신호를 사용했습니다.
주파수·위상·잡음을 source seed마다 다르게 생성했습니다.
실제 `apply_effects`로 compressor → overdrive를 렌더링했으며,
compressor는 threshold -20 dB, ratio 4, attack 10 ms, release 100 ms,
overdrive는 drive 10 dB, level 0 dB입니다. 앰프와 EQ는 이 렌더러에 없습니다.
의도된 일치/변형은 청취 평가 라벨이 아닌 실험에서 미리 정한 관계입니다.

아래는 새 별도 검증 source seed 400의 추가 꼬리 없는 결과입니다.

| 사례 | 의도된 관계 | 거리 | 이 실험에서의 판단 |
|---|---|---:|---|
| 동일 목표/출력 | 일치 | 0 | 통과 |
| 목표 + 표준편차 1e-6 잡음 | 작은 수치 잡음, 허용 사례 | 0.000398 | 통과 |
| 진폭 절반 | 의미 있는 음량 변형 | 0.095692 | 실패 |

| drive 10 → 2 dB | 노브 변형 | 0.297296 | 실패 |
| level 0 → -6 dB | 노브 변형 | 0.223034 | 실패 |

v1 기준 **0.0495790727은 무효화**했습니다. 새 기준에는 이전 v1 실험의
산정 seed 100~109, 검증 seed 200~209를 재사용하지 않았습니다.
v2의 source seed **300~309는 산정**, **400~409는 별도 검증**으로 미리 고정했습니다.
각 기본 사례에 추가 무음 **0·1·2·5초** 및 **독립 작은 잡음 꼬리 5초**를 적용했습니다.
추가 잡음의 RNG seed는 `source seed + 5000`입니다.
대부분 기본 사례는 1초, 두 번째 음 누락 사례는 3초입니다.

각 split은 source 10개 × 기본 사례 10개 × 꼬리 변형 5개 = **비교 500건**입니다.
일치 200건, 변형 300건이며 양쪽을 합쳐 1000건입니다.
이는 **총 20개 합성 source**의 파생 비교입니다. 1000개의 독립 녹음이나
새로운 기타/연주자를 검증했다는 뜻은 아닙니다.

| 분포 | 산정용 min / median / p95 / max | 별도 검증 min / median / p95 / max |
|---|---|---|
| 의도된 일치 200건 | 0 / 0 / 0.000774 / 0.000804 | 0 / 0 / 0.000457 / 0.000707 |
| 의도된 변형 300건 | 0.085538 / 0.330180 / 0.676515 / 0.745164 | 0.082858 / 0.299300 / 0.691131 / 0.724910 |

산정용 일치 최대값과 변형 최소값 사이에 틈이 있어 중간값
`T_v2 = (0.0008039283641105837 + 0.08553840054596881)/2 = 0.0431711644550397`을 얻었습니다.
**종전 v2 합성 벤치마크의 비교 규칙은 `d_v2 <= T_v2`**입니다.
이번 조용한 이벤트 진단에서는 이 규칙으로 허용/불허 라벨을 만들지 않습니다.
v1과 v2는 같은 자연로그 단위와 함수 인터페이스를 유지하지만 집계 방식과
경계 창이 달라 수치적으로 호환되지 않습니다. 기준과 저장 결과에 지표 버전을 함께 기록해야 합니다.
실험 JSON은 `metric_version`과 `invalidated_v1_threshold`를 명시합니다.
이번 보완에서는 `threshold_scope`도 추가해 작은 국소 이벤트가 미검증이고
청각적 허용 여부가 미확정임을 명시합니다. 기존 거리·산정 데이터·기준 숫자는 그대로입니다.

산정 기준을 고정하고 별도 검증했을 때 **일치 오탈락 0/200, 변형 오통과 0/300**이었습니다.
별도 검증으로 기준을 재조정하지 않았습니다.
`calibrate_audio_threshold`는 산정 분포가 겹치면 `None`을 반환하고 기준을 억지로 만들지 않습니다.

이 값은 쉬운 합성 사례를 구분하는 진단 기준입니다. 실제 기타, 미세한 노브 변화,
다른 신호 레벨·길이·표본율·장비·무음 비율, 렌더러 버전, 사람이 듣기에 허용 가능한 차이까지
검증하지 않았으므로 실제 서비스나 팀 전체의 최종 통과 기준으로 사용하면 안 됩니다.

### B. 정답 노브 복원 오차: 계산 도구 완료, 허용치 확정 불가

스키마는 `ground_truth_chain = {amp_id, chain: [{effect_type, values}, ...]}`입니다.
각 `values`는 해당 이펙터의 모든 파라미터를 포함해야 합니다.
정답과 예측의 앰프 ID, 체인 길이·순서·이펙터 종류를 먼저 비교합니다.
다르면 `structure_match=False`이며 노브 오차는 `None`입니다. 서로 다른 노브를
억지로 대응시키지 않습니다. 이 경우 복원 성공으로 처리하면 안 됩니다.
이 함수는 ID 일치만 비교하므로 실제 앰프 구현/IR 버전도 데이터에 별도로 기록해야 합니다.

연속형 파라미터의 정답 `t`, 예측 `p`, 범위 `[a,b]`에 대해:

- 원래 단위 오차: `abs(p-t)`.
- `scale` 생략/`linear`: 정규화 오차 `abs(p-t)/(b-a)`.
- `scale="log"`: `abs(log(p)-log(t))/(log(b)-log(a))`.
- 범주형/boolean: 정확히 같은 값인지 별도 비교.

로그 방식은 같은 배율의 차이를 같은 오차로 봅니다. ratio 2→4와 4→8은 같으며,
단순히 원래 숫자의 차이를 범위로 나누는 방식과 다릅니다.
이미 dB인 threshold/drive/level 등은 스키마에서 선형으로 정의되어 있어 추가 로그를 취하지 않습니다.

평균/최대는 **연속형 정규화 오차만** 대상으로 합니다. 체인 평균은 모든 연속형 노브를
동일한 가중치로 평균하며 이펙터별 평균을 다시 평균하지 않습니다.
범주형은 평균에 섞지 않으며 `categorical_all_match`로 따로 반환합니다.
범주형이 없으면 `None`, 연속형이 없으면 평균/최대가 `None`입니다.
누락·알 수 없는 키/이펙터, 범위 밖 값, NaN/Inf, 잘못된 타입은 오류로 거부합니다.
범위로 잘라내거나 기본값을 자동으로 채우지 않습니다.

```python
from metrics.parameters import evaluate_parameters, evaluate_chain

result = evaluate_parameters(
    "overdrive",
    {"drive": 10.0, "level": 0.0},
    {"drive": 2.0, "level": 0.0},
)
# per_parameter.drive: absolute_error=8 dB, normalized_error=8/15
# mean_normalized_error=0.266667, max_normalized_error=0.533333
# categorical_all_match=None

# 정답·예측 모두 chain.schema.json 형식으로 전달
# chain_result = evaluate_chain(target["ground_truth_chain"], predicted_chain)
```

ratio 4→8은 `log(2)/log(20) = 0.231378`이고 다른 compressor 노브가 같다면
평균은 `0.057845`입니다. fuzz mode만 Vintage→Modern이면 연속형 평균/최대는 0이지만
범주형 일치는 `False`입니다. 오디오 거리가 작다고 이 복원 실패가 사라지지 않습니다.

현재 쓸 수 있는 **잠정 규칙은 같은 설정을 복사한 회귀 점검에서만**
구조 일치, 평균/최대 0, 존재하는 범주형 모두 일치입니다.
실제 탐색 결과에 허용할 0보다 큰 노브 오차의 한계는 정하지 않았습니다.
예측 데이터와 팀의 노브별 허용 오차 합의가 없으므로 **최종 기준 확정 불가**입니다.
테스트 성공이나 오디오 잠정 기준으로 노브 허용치를 대신 정하지 않습니다.

## 6. 미완료 항목과 범위 밖 발견 사항

- 실제 dry/wet 오디오와 탐색 예측 결과, 허용 가능한 소리 차이의 라벨이 없어 최종 오디오 기준을 확정하지 못했습니다.
- 실제 탐색의 노브 복원 오차 분포와 파라미터별 허용 한계가 없어 실용 노브 통과 기준을 확정하지 못했습니다.
- `Create_Synthetic_pairs.py`의 라벨은 `applied_effects.compressor/gain_stage.parameters`이고,
  공통 스키마 예제의 `ground_truth_chain.chain[].values`와 다릅니다. 자동 변환/저장은 추가하지 않았습니다.
  생성 라벨을 평가할 때 아래처럼 순서를 명시하고 앰프 ID를 실제 사용 설정으로 제공해야 합니다.
  생성 스크립트는 앰프를 적용하지 않으므로 예제 `fixed_amp_v1`을 사용한 것처럼 라벨링하면 안 됩니다.
- 현재 렌더러는 fuzz `mode`를 사용하지 않습니다. 같은 dry에서 Vintage/Modern을 바꿔도
  오디오 거리 **0**인 것을 별도로 측정했습니다. 따라서 현재 렌더러로 해당 노브를 소리에서 복원할 수 없습니다.
  이 사례는 노브가 다르지만 소리는 같으므로 오디오 변형/실패 라벨 산정에서 제외했습니다.
- 현재 렌더러에는 스키마 예제의 고정 앰프·EQ 단계가 없습니다. 이번 결과는 전체 계획 체인의 검증이 아닙니다.


## 9. 작은 누락/추가음의 에너지 억제 검증

### 재현과 원인

22050 Hz, 440 Hz이며 기준은 `[진폭 0.5 순음 1초, 무음 2초]`,
비교 신호는 `[같은 순음 1초, 무음 1초, 추가 순음 1초]`입니다.
순서를 바꾸면 추가음 대신 누락음이 되며 대칭 지표라 점수는 같습니다.
아래 국소 오차는 알려진 마지막 1초 구간과 겹치는 STFT 창에서만 계산했습니다.

| 추가 진폭 | 공통 첫 음 대비 | v2 전체 거리 | 이벤트 에너지 비중 | 이벤트 국소 에너지 평균 | 활성 프레임 균등 평균 |
|---|---:|---:|---:|---:|---:|
| 0.5 | 0 dB | 0.268639051 | 약 50% | 0.537278 | 0.393707 |
| 0.05 | -20 dB | 0.002437709 | 약 0.9901% | 0.246209 | 0.179827 |
| 0.005 | -40 dB | 0.000008735 | 약 0.009999% | 0.087361 | 0.058455 |

같은 주파수·길이의 분리된 순음에서 에너지는 진폭의 제곱에 비례합니다.
추가 진폭을 `A`라 하면 이벤트 비중은 대략 `A²/(0.5² + A²)`입니다.
공통 첫 음의 오차가 0이므로 이 사례의 전체 거리는
**이벤트 비중 × 이벤트 국소 오차**로 설명됩니다.
진폭 0.05는 국소 오차보다 약 **101배**, 0.005는 약 **10001배** 작은 전체 점수가 됩니다.
그 외에도 하한 아래 주파수 bin이 늘어나면서 진폭이 낮을수록 국소 로그 오차 자체도 작아집니다.

이는 한쪽 소리를 마스크가 제거해서 생긴 현상이 아닙니다. 실제로 활성으로 포함되지만
가중치가 작습니다. **포함되는 것과 충분히 검출되는 것은 다릅니다.**
종전 참고값 0.043171과 기계적으로 비교하면 0.05·0.005 사례는 작지만,
이를 청각적으로 허용되는 결과라고 해석할 근거는 없습니다.

### 추가 측정

다음은 기본 추가 진폭 0.05, 공통 첫 음 1초, 내부 쉼표 1초의 예입니다.
감쇠는 `A*exp(-t/tau)*sin(...)`입니다. 절단은 비교할 두 신호의 앞부분을 같게 두고
해당 시점 이후의 이벤트만 한쪽에서 지웠습니다.

| 변화 | v2 거리 |
|---|---:|
| 지속 추가음 0.1초 / 1초 / 5초 | 0.001482 / 0.002438 / 0.006523 |
| 2초 감쇠음, tau 0.1초 / 0.5초 / 2초 | 0.000534 / 0.000864 / 0.001554 |
| 2초 서스테인의 0.5초 이후 누락 | 0.003607 |
| 2초 감쇠음(tau 0.5초)의 1.5초 이후 누락 | 약 0.000000813 |
| 내부 쉼표 0.25초 / 5초 | 0.002433 / 0.002466 |
| 같은 추가음, 공통 큰 소리 0.25초 / 8초 | 0.009450 / 0.000310 |

내부 쉼표에 따른 약 1.37% 차이는 뒤 이벤트의 STFT 격자 위치가 달라지는 영향입니다.
프레임 단위로 보면 0인 무음이 계속 분모에 쌓이는 v1의 현상과 다릅니다.
외곽에 정확한 무음 2·5초를 붙여도 위 조용한/감쇠/절단 사례의 v2 점수는
테스트에서 소수점 12자리까지 같았습니다.
반면 **공통으로 잘 맞춘 큰 소리를 길게 늘려도 같은 작은 오류의 점수는 줄어듭니다.**
이벤트의 중요성을 전체 평균 하나로 판단할 때 생기는 별도의 위험입니다.

### 대안과 변경 판단

| 집계 | 기대 효과 | 한계 |
|---|---|---|
| 현재 v2 에너지 평균 | 공통 무음 무게 0, 큰 소리·경계 안정성 | 작은 이벤트가 진폭 제곱·전체 길이에 의해 약하게 반영됨 |
| 활성 프레임 균등 평균 | 진폭 제곱에 따른 프레임 가중치 억제 제거 | 약한 경계/잡음에 민감, 잘 맞는 구간이 길어지면 여전히 국소 오류 희석 |
| 제곱근 에너지 평균 | 가중치의 진폭 제곱 효과 완화 | 여전히 작은 소리/짧은 이벤트 억제, 물리·청각적 정당성이 검증되지 않음 |
| 프레임 p95 / 최대 | 큰 국소 오류를 따로 관찰 | p95는 짧은 이벤트를 놓칠 수 있고 최대는 한 프레임 경계·클릭에 민감 |
| 구간별 오차와 별도 이벤트 보존 평가 | 국소 오류와 전체 거리 분리 가능 | 실제로 쓸 구간·최소 길이·활동 검출/정답 이벤트 라벨이 필요 |

진폭 0.05 사례의 제곱근 에너지 평균은 0.025454, 프레임 p95는 1.491349,
최대는 2.492542였습니다. **v2의 참고값을 다른 집계에 재사용하면 안 됩니다.**
진단 도구의 국소 구간은 합성 생성 시 알고 있는 범위입니다. 실제 신호에서
자동 검출했다거나 청취 중요도를 추정한 결과가 아닙니다.

**판단:** 이벤트 보존을 단독 판정하는 용도로는 v2 전체 거리와 종전 참고값이 부족합니다.
검증·적용 범위 표시는 보완할 필요가 있어 이번에 변경했습니다.
하지만 청취 라벨 없이 임의의 다른 집계·혼합 가중치·더 낮은 기준으로 바꾸는 것은
정당화할 수 없어 거리 함수와 지표 버전은 유지했습니다. 새로운 통과 기준은 정하지 않았습니다.

실제 기타에서는 음역·강약·재생 레벨·배경 잡음별로 추가/누락음, 서스테인·잔향 절단,
긴 내부 쉼표와 공통 연주 길이를 바꾼 사례를 수집해야 합니다.
각 오류 구간과 청취 허용/불허 라벨을 기록하고 원본 연주/연주자/세션 단위로
산정·검증 그룹을 먼저 나눈 뒤 후보 집계의 국소 오류 검출·오경보를 비교해야 합니다.
그 결과로 교체 여부와 별도 기준을 결정하고, 별도 검증 자료에서 확인해야 합니다.

## 10. 2026-11-05 하한 -80 dB 변경 및 검증

### 변경 범위와 해석

```python
NOISE_FLOOR_DB = -80.0
MAGNITUDE_FLOOR = STFT_SINE_REFERENCE * 10 ** (NOISE_FLOOR_DB / 20)
# 512 * 10**(-80/20) = 0.0512
METRIC_VERSION = "log_stft_joint_active_energy_v2_floor_m80db"
```

이 값은 고정 참조 512에 대한 STFT 크기 하한입니다. 로그 직전에 양쪽에 똑같이
적용합니다. 입력별 peak/음량 정규화는 하지 않습니다. FFT/창 2048, hop 512,
Hann 창, 양 끝 창 완성, 합집합 활성 조건과 에너지 가중 평균은 그대로입니다.
최종 거리는 자연로그 단위이며 dB가 아닙니다.
주요 함수 본문의 AST를 변경 전과 비교해 STFT·입력 검증·집계 코드가 동일함을 확인했습니다.

기존 -120 dB의 하한 0.000512보다 STFT 크기 기준으로 100배 높습니다.
진폭 1인 bin 중심 순음 참조에서 -80 dB에 해당하는 진폭은 약 1e-4입니다.
그러나 모든 파형의 RMS에 적용되는 절단 기준은 아닙니다. 주파수 위치·DC·창 경계에
따라 대응이 다릅니다. 새로운 하한은 **작은 잡음뿐 아니라 작은 유효음도 지웁니다.**
서로 다른 두 작은 신호가 모두 하한 아래이면 거리 0이 될 수 있습니다.

## 11. Step 1: Dynamics 거리 (2026-11-10)

`dynamics_distance(x, y, sample_rate)`는 **시간에 따른 음량의 차이**를 독립적인
Python `float`로 반환합니다. 전체 음량, 어택(커지는 부분), 서스테인(유지되는 부분),
릴리즈(줄어드는 부분), 컴프레서가 바꾼 음량 곡선을 비교합니다.
점수 0은 **측정한 음량 곡선이 같음**을 뜻하며 파형 자체나 청각적 유사성이 같다는 뜻은 아닙니다.
단위는 평균 절대 **dB 차이**이고 0~1로 제한되지 않습니다.

```python
from metrics.dynamics import dynamics_distance

# 같은 표본율, 길이, 시간 정렬, 공통 진폭 기준의 모노 배열
score = dynamics_distance(reference_audio, rendered_audio, sample_rate=16000)
```

### 계산과 초기 설정의 근거

1. 직사각형 **30ms 프레임**에서 RMS(짧은 구간의 평균적인 음량)를 구합니다.
   **10ms 간격**으로 옮기며 계산합니다. 표본 수는 `round(sample_rate * ms / 1000)`이며
   최소 1개입니다. 30ms는 개별 파형의 빠른 진동을 평균내면서 음량 곡선의 변화를
   남기기 위한 초기 절충입니다. 10ms hop은 겹치는 창으로 변화를 관찰하는 간격입니다.
   20/50ms보다 최적이라고 검증한 설정은 아닙니다. 아주 빠른 어택은 흐려질 수 있고,
   저음의 주기·위상에 따라 RMS가 흔들릴 수 있습니다. 더 작은 hop도 30ms 창의 흐림을 없애지는 않습니다.
2. 고정 RMS 참조 **1**에 대해 `20 * log10(max(RMS, 1e-5))`를 계산합니다.
   하한은 **-100 dBFS**, 즉 RMS `1e-5`입니다. 진폭 1인 일정 신호의 RMS는 1이고,
   충분히 긴 진폭 1 순음의 RMS는 약 `1/sqrt(2)`이므로 약 -3.01 dBFS입니다.
   스펙트럼 지표의 **STFT 참조 512 / 크기 하한 0.0512 / -80 dB와 별개**입니다.
3. 어느 한쪽이라도 RMS가 하한을 **초과**하는 프레임을 포함합니다(OR).
   그 프레임들의 두 dB 값 차이의 절댓값을 **동일한 비중으로 평균**합니다.
   한쪽에만 존재하는 소리도 포함하고, 양쪽 모두 하한 이하인 프레임은 분모에도 넣지 않습니다.
   활성 프레임이 없으면 `0.0`을 반환합니다.
4. 신호와 겹치는 모든 hop 격자의 창을 양 끝에서 0으로 완성하고, 항상 전체 창 길이로
   RMS를 계산합니다. 따라서 뒤에 정확한 공통 무음을 붙여도 새로운 비영 창이 생기지 않아
   점수가 희석되지 않습니다. 선행 무음은 hop의 배수인 경우 같은 격자를 유지합니다.
   임의의 시간 이동이나 내부 구간 이동에 대한 불변성을 보장하지는 않습니다.

```text
R_x[t] = sqrt(mean(x_frame[t] ** 2))
L_x[t] = 20 * log10(max(R_x[t], 1e-5))
active[t] = max(R_x[t], R_y[t]) > 1e-5
dynamics_distance = mean(abs(L_x[t] - L_y[t]) for active frames)
```

입력별 정규화·peak 보정·자동 시간 정렬은 하지 않습니다. 입력 순서를 바꿔도 같은 값입니다.
활성 프레임을 균등하게 평균하는 이유는 큰 어택의 에너지가 조용한 서스테인·릴리즈의
차이를 과도하게 누르는 일을 피하기 위해서입니다. 대신 하한 근처의 잡음과 경계 프레임에도
같은 비중을 줍니다. 긴 일치 **유음** 구간이 늘어나면 짧은 오류는 여전히 희석될 수 있습니다.
이를 청각적으로 최적인 집계라고 주장하지 않습니다.

하한은 작은 수치 잡음과 유효음 보존의 초기 절충입니다. 같은 16000 Hz/1초/440 Hz
순음과 seed 42, 표준편차 `1e-6` Gaussian 잡음에서 후보 하한을 비교했습니다.
아래 값은 모두 **RMS 방식**으로 직접 계산했으며 스펙트럼 점수가 아닙니다.

| RMS 하한 후보 | 무음 ↔ 잡음 | 무음 ↔ 순음 peak 1e-4 | 무음 ↔ 순음 peak 1e-5 |
|---|---:|---:|---:|
| -80 dBFS | 0 | 0 | 0 |
| **-100 dBFS (선택)** | **0** | **16.862584** | **0** |
| -120 dBFS | 0.213386 | 36.862584 | 16.862584 |

선택값은 이 잡음을 제외하면서 peak `1e-4` 순음을 남깁니다.
**peak `1e-5` 순음은 실제로 존재해도 하한 아래이므로 무음과 구별되지 않습니다.**
이는 수치 잡음만 제거하는 완벽한 구분이 아닙니다. 실제 기타·장비 잡음·청취 결과로
하한과 프레임 설정을 검증하지 않았으며 최종값이나 청각적 허용 기준이 아닙니다.
잡음도 RMS가 하한을 넘으면 평가됩니다. 하한 아래 잡음도 유음에 섞이면 점수가 조금 변할 수 있습니다.

### 입력 조건과 오류

- 같은 길이의 비어 있지 않은 1차원 실수 모노 배열/숫자 목록을 받습니다.
  빈 입력, stereo/고차원/스칼라, 문자·bool·복소수·object, NaN/Inf 등은 `ValueError`입니다.
- `sample_rate`는 양쪽에 공통인 정수 Hz입니다. `16000.0` 같은 정수값 실수도 허용합니다.
  bool, 문자열, 두 표본율의 목록/튜플, 0/음수/비정수/NaN/Inf는 `ValueError`입니다.
  과도한 분석 창 할당을 막기 위해 지원 범위를 **1~768000 Hz**로 제한합니다.
  이는 자원 보호 범위이며 모든 표본율에서의 음향적 타당성을 뜻하지 않습니다.
- 서로 다른 원본 표본율은 호출자가 먼저 공통 표본율로 변환해야 합니다.
  함수는 재표본화를 하지 않습니다. **배열에는 표본율 정보가 없으므로 길이가 같으면
  원래 표본율의 불일치를 자동 검출할 수 없습니다.** 시간 정렬과 공통 진폭 기준도 호출자가 확인합니다.
- full scale을 1로 둔 공통 실수 진폭을 권장합니다. 정수도 원래 숫자 크기로 받으므로,
  PCM 정수는 양쪽 모두 같은 full-scale 기준으로 먼저 실수 변환해야 합니다.
  1보다 큰 값도 자르거나 정규화하지 않습니다. RMS 제곱/합이 넘치는 극단값은
  명확한 `ValueError`로 거부합니다. 계산 가능한 큰 유한값은 허용합니다.
- 양쪽 모두 무음이면 오류 대신 `0.0`입니다. 입력 배열은 변경하지 않습니다.

### 인터페이스와 계산식

새 파일 `metrics/combined.py`는 다음 두 함수를 제공합니다. 인자는 두 함수가 같습니다.

```python
combined_distance(
    x, y, sample_rate, *,
    spectral_weight, dynamics_weight, spectral_scale, dynamics_scale,
) -> float

combined_distance_details(
    x, y, sample_rate, *,
    spectral_weight, dynamics_weight, spectral_scale, dynamics_scale,
) -> CombinedDistanceResult
```

첫 번째는 탐색 엔진에서 사용할 **결합 점수 하나(Python float)**를 반환합니다.
두 번째는 같은 계산을 하면서 아래 내역을 함께 반환합니다. 점수가 작을수록 측정한 차이가 작습니다.

| 결과 필드 | 의미 |
|---|---|
| `combined` | 결합 거리 |
| `spectral` | 기존 `spectral_distance(x, y)`의 원점수: 자연로그 크기 차이 |
| `dynamics` | 기존 `dynamics_distance(x, y, sample_rate)`의 원점수: 평균 절대 dB 차이 |
| `scaled_spectral`, `scaled_dynamics` | 각각의 원점수를 지정한 스케일로 나눈 값 |
| `spectral_weight`, `dynamics_weight` | 합이 1이 되도록 정규화한 실제 가중치 |
| `spectral_scale`, `dynamics_scale` | 호출자가 지정한 실제 나눗셈 기준값 |

```text
a = spectral_weight / (spectral_weight + dynamics_weight)
b = dynamics_weight / (spectral_weight + dynamics_weight)
scaled_spectral = spectral_distance(x, y) / spectral_scale
scaled_dynamics = dynamics_distance(x, y, sample_rate) / dynamics_scale
combined = a * scaled_spectral + b * scaled_dynamics
```

가중치는 비중으로 받습니다. 예를 들어 `3, 2`는 `0.6, 0.4`로 처리합니다.
구현은 매우 큰 가중치의 합이 넘치지 않도록 두 값을 먼저 같은 최댓값으로 나눈 뒤 합으로 나눕니다.
합이 1인 값도 그대로 사용할 수 있습니다(부동소수점 반올림 범위).

Spectral은 자연로그 단위이고 Dynamics는 dB 단위이므로 **원점수를 바로 더하지 않습니다.**
각 스케일은 해당 지표와 같은 단위의 양수 기준값입니다. 나눈 결과는 단위 없는 상대 점수가 됩니다.
이는 0~1 정규화나 청각적 유사성 확률이 아니며, 1을 넘을 수 있습니다.
단위를 맞췄다고 두 점수의 청각적 중요성까지 같아지는 것은 아닙니다.

**두 가중치와 두 스케일은 모두 필수 인자입니다. 기본값·자동 추정·최적값은 없습니다.**
스케일은 명시적인 실험 설정값 또는 산정용 데이터 전체의 점수 분포에 근거한 고정값을 사용해야 합니다.
이번에는 실제 데이터 기반 스케일을 산정하지 않았고, 자동 산정 함수도 만들지 않았습니다.

### 사용 예제와 이후 탐색 엔진에서 호출하는 방법

아래 숫자는 **계산을 보여 주기 위한 임시 예시**입니다.
`50:50`, Spectral 스케일 `1`, Dynamics 스케일 `10 dB`는 데이터로 검증한 값이나 권장값이 아닙니다.

```python
from metrics.combined import combined_distance, combined_distance_details

# 아래 네 값은 예제 전용. 실제 적용 시 팀이 결정한 고정 설정으로 교체합니다.
example_settings = dict(
    spectral_weight=1.0,
    dynamics_weight=1.0,
    spectral_scale=1.0,
    dynamics_scale=10.0,
)

# x, y: 같은 표본율·길이·시간 정렬·공통 진폭 기준의 모노 배열
result = combined_distance_details(x, y, sample_rate, **example_settings)
print(result.spectral, result.dynamics, result.combined)
score = combined_distance(x, y, sample_rate, **example_settings)
assert score == result.combined
```

나중에 탐색 엔진에서 호출할 때는 팀이 선택한 네 설정을 `metric_settings`에 담아 고정합니다.
매 후보마다 스케일을 다시 계산하지 않습니다. 현재 탐색 코드는 수정하지 않았습니다.

```python
# metric_settings: 팀이 별도로 결정한 가중치 2개와 스케일 2개
loss = combined_distance(wet, target_audio, sample_rate, **metric_settings)
```

Spectral만 사용하려면 가중치 `1, 0`, Dynamics만 사용하려면 `0, 1`로 지정합니다.
결합 결과는 선택한 지표의 **원점수 / 해당 스케일**입니다.
그 스케일을 `1`로 지정하면 기존 함수의 원점수와 같습니다.
가중치가 0인 지표도 원점수를 반환하고 기존 입력 검증을 보존하기 위해 실제로 계산합니다.
따라서 어느 경우든 유효한 `sample_rate`와 두 스케일이 필요하며, 두 지표의 계산 비용이 듭니다.

### 입력 안전성과 유지한 기존 동작

- 두 기존 거리 함수를 직접 호출합니다. 기존 계산식과 호출 방식은 바꾸지 않았습니다.
  입력별 음량 정규화·재표본화·시간 정렬·클리핑을 하지 않으며 입력 배열도 변경하지 않습니다.
- 두 파형은 길이가 같은 비어 있지 않은 1차원 유한 실수 배열이어야 합니다.
  문자, bool, 복소수, NaN/Inf, 다차원, 길이 불일치 등은 기존 함수의 검증으로 거부합니다.
  PCM 정수는 호출자가 같은 full-scale 기준의 실수로 변환해야 합니다.
- `sample_rate` 규칙은 기존 Dynamics와 같습니다. 정수값 실수도 허용하는 공통 정수 Hz,
  범위는 1~768000입니다. bool·문자열·비정수·NaN/Inf·서로 다른 두 rate의 목록 등은 거부합니다.
  배열에 rate 정보가 없으므로 원본 표본율의 일치 여부와 시간 정렬은 호출자가 확인해야 합니다.
- 가중치는 유한한 0 이상 실수이고 적어도 하나는 양수여야 합니다.
  두 스케일은 모두 유한한 양수입니다. bool·문자열·복소수·배열은 설정값으로 받지 않습니다.
  잘못된 설정과 입력은 `ValueError`, 필수 인자 누락은 Python의 `TypeError`입니다.
- 계산 가능한 동일 신호는 0이고 입력 순서에 대칭입니다. 반환되는 점수는 음수가 아닌 유한한
  Python float입니다. 극단적인 입력의 기존 계산 오버플로와 너무 작은 스케일로 인한
  무한대 결과는 `ValueError`로 거부합니다. 가중치 0이나 동일 입력도 검증을 건너뛰지 않습니다.
- Spectral의 **-80 dB / STFT 크기 하한 0.0512**와 Dynamics의
  **-100 dBFS / RMS 하한 1e-5**는 그대로 별개입니다. 둘을 같은 임계값으로 취급하지 않습니다.
  서로 다른 파형도 하한이나 각 지표의 측정 특성 때문에 점수가 0일 수 있습니다.
- 공통 무음을 뒤에 추가해도 기존 지표의 점수가 희석되지 않는 동작을 유지합니다.
  임의의 선행 무음·시간 이동에 대한 불변성은 보장하지 않습니다.
