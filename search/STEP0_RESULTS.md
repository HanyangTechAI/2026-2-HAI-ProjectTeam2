# Step 0 검증 결과: Overdrive 노브 복원

> 결론: **통과** (CMA-ES 최종 성공 100%, Random Search 91%)

## 1. 설정

| 항목 | 값 |
|---|---|
| 데이터 | 정답 데이터 중 Overdrive 234쌍 (IDMT-SMT-Guitar V2, Fender Strat Clean, 컴프 없음) |
| 탐색 노브 | `drive` 0~15dB, `level` -12~12dB |
| 탐색 방법 | Random Search / CMA-ES (50회 × 4번 재시작) |
| 예산 | 파일당 200회 렌더링, 시드 1개 |
| 비교 구간 | dry에서 가장 소리가 큰 1초 구간 |
| 거리 함수 | log-STFT 스펙트럼 거리 (-80dB 하한) |
| 노브 오차 | \|찾은 값 - 정답\| / 노브 범위 (%) |

재현 방법 (프로젝트 루트):

```bash
python -m search.evaluate_dataset              # 평가 → outputs/search/dataset_overdrive.csv
python -m search.evaluate_dataset --examples   # 오디오 예시 → outputs/search/examples/
```

## 2. 통과 기준

- 파일 하나에 대해 **노브 오차가 모두 5% 이내** 또는 **소리 거리 0.00936 이하**이면 성공입니다.
- 성공률이 90% 이상이면 통과입니다.
- 0.00936은 `metrics/README.md`의 잠정 참고값(-80dB 하한)입니다.
- 소리 기준을 함께 쓰는 이유: drive가 낮으면 Overdrive가 거의 볼륨 조절처럼 동작합니다. 그래서 drive와 level을 다르게 조합해도 같은 소리가 납니다. 이 경우는 탐색이 틀린 게 아니라, 정답이 여러 개인 것입니다.

## 3. 결과

| 방법 | 평균 노브 오차 | 노브 성공 | 소리 성공 | 최종 성공 | 판정 |
|---|---|---|---|---|---|
| Random Search | 9.1% | 38% | 87% | 91% | 통과 |
| CMA-ES | 6.0% | 59% | 99% | **100%** | **통과** |

CMA-ES의 정답 drive 구간별 노브 성공률:

| 정답 drive | 0~3dB | 3~6dB | 6~9dB | 9~12dB | 12~15dB |
|---|---|---|---|---|---|
| 노브 성공 | 22% | 39% | 56% | 80% | 84% |

- CMA-ES에서 노브는 틀렸지만 소리는 맞은 95개는 모두 소리 거리가 0.0069 이하였습니다.
- 이런 경우는 정답 drive가 낮을수록 많습니다. 탐색 실패가 아니라 drive와 level이 같은 역할을 해서 생기는 현상입니다.
- Random Search 실패 21개는 모두 정답 drive가 9dB 이상입니다. 같은 예산으로는 정밀하게 맞추지 못했습니다.

## 4. 오디오 예시

`python -m search.evaluate_dataset --examples`로 생성합니다 (`outputs/search/examples/`).
사례마다 `_dry`, `_truth`(정답), `_found`(찾은 노브로 렌더링) 3개 파일이 있습니다.

| 파일 | 사례 | 정답 (drive, level) | 찾은 값 | 노브 오차 | 소리 거리 |
|---|---|---|---|---|---|
| `1_cma_knob_ok` | CMA-ES, 노브까지 맞음 | 10.38, -4.65 | 10.36, -4.61 | 0.2% | 0.0003 |
| `2_cma_audio_only` | CMA-ES, 다른 노브로 같은 소리 | 1.49, 4.84 | 8.81, -2.30 | 48.8% | 0.0043 |
| `3_random_fail` | Random Search 실패 | 14.84, 4.33 | 13.89, 5.96 | 6.8% | 0.0371 |

## 5. Step 1로 넘길 사항

- 이펙터와 노브가 늘어나면 "다른 노브, 같은 소리" 사례가 더 많아집니다. 평가 방식(노브 기준 / 소리 기준)을 다시 정해야 합니다.
- 소리 기준값 0.00936은 잠정값입니다. 이펙터가 늘어나면 다시 확인해야 합니다.
