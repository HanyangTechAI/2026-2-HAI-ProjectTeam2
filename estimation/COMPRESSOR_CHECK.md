# 컴프레서 작동 및 학습 데이터 점검 — 2026-11-17

컴프레서 구현과 노브 전달은 정상이다. 다만 현재 데이터의 컴프 ON 라벨 중 약 29%는
현재 렌더러에서 bypass와 같거나 아주 작은 차이만 발생한다. 구조상 컴프가 존재한다는
라벨과 실제 압축이 들리는지는 구분해야 한다.

## 확인 범위와 방법

- 기존 2,730쌍의 로컬 캐시에서 컴프 ON 라벨 **1,345개**를 전부 검사했다.
  컴프 OFF는 1,385개다.
- 생성 폴더 `dry/`에서 캐시한 원래 44,100 Hz 파형 78개를 사용했다.
  입력 피크는 모두 약 −12 dBFS이며 추가 정규화하지 않았다.
- `effects.render.build_effect('compressor', values)`로 실제 Pedalboard Compressor를 만들고,
  네 노브의 설정값을 확인한 뒤 `Pedalboard(...)(dry, rate, reset=True)`로 처리했다.
- VST 드라이브 이전의 **컴프 단독 출력과 동일 Dry를 비교**했다.
  전체 체인의 드라이브·EQ 마스킹 효과를 측정한 결과는 아니다.
- 공유 데이터, 생성 정책, 라벨, 모델은 변경하지 않았다. 재학습도 실행하지 않았다.

현재 코드에서 컴프는 선택적으로 체인의 맨 앞에 연결된다. 스키마의 범위는
threshold −60~0 dB, ratio 1~20, attack 0.1~100 ms, release 10~1,000 ms다.
`effects/render.py`는 이 네 값을 Compressor 생성자에 전달하고,
`estimation/renderer.py`도 컴프에는 같은 builder를 사용한다.
기본값을 쓰는 경우 threshold −18 dB, ratio 4, attack 5 ms, release 100 ms다.
이는 VST 내부 컴프가 아닌 Pedalboard 내장 컴프다.

## 전체 컴프 ON 라벨 측정

| 조건 | 개수 / 1,345 | 비율 |
|---|---:|---:|
| 입력과 출력의 파형 차이가 0 | 365 | 27.14% |
| bypass에 가까움 — 아래 수치 기준, 위 365개 포함 | 393 | 29.22% |
| threshold가 입력 피크 이상 | 287 | 21.34% |
| ratio ≤ 1.1 | 41 | 3.05% |
| 전체 파형 RMS 감소량 < 1 dB | 509 | 37.84% |

각 행은 겹칠 수 있다. bypass에 가깝다는 기준은 상대 RMS 파형 오차 < 0.01이면서
전체 RMS 레벨 감소량의 절댓값 < 0.1 dB다. 이는 감사용 수치 기준이며 청감 역치는 아니다.
감사 스크립트의 `unchanged` 판정 허용오차는 상대 RMS ≤ 1e-6이고,
이번에 해당한 365개는 실제 최대 샘플 차이도 0이었다.

피크가 −12 dBFS이므로 threshold ≥ −12 dB인 287개에는 압축이 걸리지 않았다.
threshold가 피크보다 낮은데도 변화가 없는 경우가 78개 더 있었다.
따라서 순간 피크 초과만으로 작동을 보장할 수 없다. attack을 포함한 검출기의
시간 응답을 거친 실제 출력도 검사해야 한다. ratio ≤ 1.1인 41개 중 26개는
위의 bypass 근접 기준에 해당했다.

컴프 ON 전체의 RMS 감소 중앙값은 **3.97 dB**, 최댓값은 **36.29 dB**다.
무효 압축뿐 아니라 매우 큰 감쇠도 섞여 있다. 이 감소량은 전체 파형 에너지에 따른 값이며,
순간 gain reduction 또는 컴프 이후 드라이브의 출력 레벨과 다르다.

## 동일 Dry 78개에 대한 대조 실험

| 설정 | 전체 RMS 감소 중앙값 | 결과 |
|---|---:|---|
| ratio=1, threshold=−40 dB, 나머지 기본값 | 0 dB | 78개 모두 입력과 같음 |
| threshold=0 dB, 나머지 기본값 | 0 dB | 78개 모두 입력과 같음 |
| 모든 노브 기본값 | 0.16 dB | 감소량 범위 0~0.63 dB |
| threshold=−35 dB, ratio=4, attack=1 ms, release=100 ms | 10.31 dB | 78개 모두 압축, 감소량 6.77~11.53 dB |

총 312회 대조 측정이다. 강한 설정에서 실제 압축이 발생하고 무효 설정에서 입력을
그대로 내보내므로, 컴프가 연결되지 않거나 노브를 무시하는 문제는 확인되지 않았다.
현재 입력에서는 기본 threshold=−18 dB도 압축이 약할 수 있다.

## 저장된 CNN 결과와의 관계

아래는 재학습 없이 기존 best epoch 20의 컴프 ON/OFF 예측을 활동도별로 나눈 것이다.
표의 정확도는 해당 행에서만 계산한 ON/OFF 정답률이다.

| 정답 컴프 상태 | Validation | Test |
|---|---:|---:|
| 컴프 OFF | 127/212 = 59.9% | 147/226 = 65.0% |
| 컴프 ON이나 출력 변화 0 | 23/57 = 40.4% | 24/53 = 45.3% |
| 컴프 ON, bypass 근접 기준보다 큰 변화 | 126/150 = 84.0% | 103/138 = 74.6% |

근접하되 변화 0은 아닌 표본은 validation 1개, test 3개로 위 표에서 제외했다.
전체 컴프 사용 여부 정확도는 기존대로 validation 66.0%, test 65.5%다.
위 차이는 무효 압축 표본이 예측을 어렵게 한다는 해석과 부합하지만,
현재 정확도의 원인을 이것 하나로 확정하는 실험은 아니다.
특히 컴프가 없는 표본에서도 오탐이 발생하고, 후속 드라이브가 압축 차이를 가릴 수 있다.

## 다음 데이터 생성에 권장하는 조치

1. 컴프 ON 표본은 임의 노브를 뽑은 후 실제 컴프 출력과 bypass를 비교해 재샘플링한다.
   ratio ≥ 2 같은 제한과 함께, 유효 구간의 gain reduction 및 지속 시간을 확인한다.
   예를 들어 최소 1 dB 압축 같은 기준은 시작점으로 검토할 수 있으나 아직 검증된 기준은 아니다.
2. threshold는 −12 dBFS 피크만 보지 말고 Dry의 레벨·엔벌로프에 맞춰 선택한다.
   attack이 길면 순간 피크를 넘어도 압축이 없을 수 있다.
3. 컴프 OFF 표본은 별도로 유지한다. 기존의 구조상 ON 라벨을 소리가 작다는 이유만으로
   임의로 OFF로 바꾸지 않는다. 구조 존재 여부와 유효 압축 여부를 별도로 기록하는 방법도 있다.
4. 같은 Dry·드라이브·EQ·노브를 고정한 컴프 ON/OFF 쌍으로 전체 체인에서도 차이가 남는지 확인한다.
   현재 점검은 컴프 단독이다. 생성 렌더러가 확정되면 같은 정책으로 새 데이터를 생성하고 재학습한다.

현재 설치 렌더러가 저장 Wet을 정확히 재현하지 않는 기존 문제가 있으므로,
이번 결과는 **현재 컴프 구현과 저장 라벨을 사용한 진단**이다.
역사적으로 저장된 Wet 생성의 모든 세부 동작까지 검증한 것으로 해석하지 않는다.
